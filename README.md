# 课堂签到系统

> 软件工程课内实验一 · 软件工具的使用 —— 签到系统示例项目

## 一、项目背景

课堂考勤长期依赖纸笔点名：教师逐个念名字、学生在纸上打钩，课后还要人工统计迟到人数，
既慢又容易出错，纸质记录也难以长期保存和检索。

本项目是实验一的实践载体，用一个**最小但完整**的 Web 应用替代上述流程：
学生输入学号与姓名即完成签到，教师端实时看到签到人数、迟到人数与完整记录，
并可一键导出为 Excel 可直接打开的表格。

项目刻意采用 **Python 标准库实现、零第三方依赖**，目的是让助教或教师拿到代码后
无需安装任何包（不需要 pip、不需要虚拟环境），装好 Python 就能直接运行、当堂验证。
同时它保留了一个软件项目应有的基本结构：分层的数据访问、独立的 Web 服务、
前后端分离的静态资源、忽略规则与规范化的提交历史。

## 二、项目目标

| 目标 | 达成方式 |
|---|---|
| 替代纸质点名，降低考勤成本 | 学生自助输入学号姓名，一次提交即完成签到 |
| 杜绝重复签到 | 数据库唯一索引在存储层兜底，并发提交也不会产生重复记录 |
| 让教师快速掌握出勤情况 | 页面实时展示当日签到人数、正常人数、迟到人数 |
| 考勤记录可留存、可分析 | 支持一键导出带 BOM 的 CSV，Excel 双击打开不乱码 |
| 输入健壮、边界清晰 | 学号、姓名的格式与长度在写入前统一校验 |

## 三、功能特性

- **学生签到**：输入学号与姓名完成签到，提交后即时反馈成功或失败原因
- **重复签到拦截**：同一学号同一天只允许签到一次
- **迟到自动判定**：晚于 08:30:00 签到自动标记为「迟到」，否则记为「正常」
- **实时统计**：当日已签到、正常、迟到三项人数
- **签到记录列表**：按时间倒序展示学号、姓名、签到时间与状态
- **导出 CSV**：一键导出全部记录，带 UTF-8 BOM，Excel 直接打开中文正常
- **输入校验**：学号必须为 4–20 位 ASCII 数字，姓名非空
- **零第三方依赖**：仅使用 `http.server`、`sqlite3`、`csv`、`json` 等标准库

## 五、运行方式

```bash
# 1. 克隆仓库
git clone <本仓库地址>
cd checkin-system

# 2. 启动服务（无需安装任何依赖）
python app.py
```

启动后终端会输出：

```
签到系统已启动 -> http://127.0.0.1:8000
按 Ctrl+C 停止服务
```

浏览器打开 <http://127.0.0.1:8000> 即可使用。首次启动会自动创建 `checkin.db` 并建表。

运行实验一步骤 5 的最小示例：

```bash
python hello_ai.py
# 输出：Hello, AI 编程！
```

## 七、接口说明

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 签到页面 |
| GET | `/static/*` | 静态资源 |
| POST | `/api/checkin` | 提交签到，请求体 `{"student_id": "...", "name": "..."}` |
| GET | `/api/records` | 最近 100 条签到记录（JSON） |
| GET | `/api/stats` | 当日签到统计（JSON） |
| GET | `/api/export.csv` | 导出全部签到记录（CSV，带 BOM） |

签到成功返回 `200`，被拒绝（参数非法 / 今日已签到）返回 `409` 并附带 `reason` 字段。

命令行快速验证：

```bash
curl -X POST http://127.0.0.1:8000/api/checkin \
     -H "Content-Type: application/json" \
     -d '{"student_id": "20230001", "name": "张三"}'
```

## 八、数据库设计

单表 `checkin`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER | 主键，自增 |
| `student_id` | TEXT | 学号 |
| `name` | TEXT | 姓名 |
| `checkin_at` | TEXT | 签到时间，格式 `YYYY-MM-DD HH:MM:SS` |
| `status` | TEXT | `正常` 或 `迟到` |

唯一索引 `idx_student_per_day` 建立在 `(student_id, substr(checkin_at, 1, 10))` 上，
在**存储层**保证「同一学号同一天只有一条记录」，而不是只靠应用层判断——
这样即使多个请求同时到达，也不会写入重复数据。

## 九、实验一 · AI 工具使用说明

按实验要求，此处如实说明 AI 工具的**用途与范围**：

| 环节 | AI 参与程度 | 说明 |
|---|---|---|
| 项目结构与核心代码 | AI 生成初稿 | `db.py`、`app.py`、前端三件套由 AI 生成，人工逐行走查并实际运行验证 |
| 步骤 5 最小示例 | AI 生成 + 人工微调 | 初版直接 `print`，人工改为 `greet()`/`main()` 结构 |
| 缺陷发现 | **人工主导** | 两处缺陷由人工构造请求实测发现，非 AI 主动指出 |
| 缺陷修复 | AI 生成 + 人工验证 | 修复方案由 AI 给出，人工复测确认且回归通过 |
| 功能扩展（导出 CSV） | AI 生成 + 人工验证 | 人工提出需求，实现中发现中文文件名导致响应中断的问题 |

**人工校验的实际作用**：AI 生成的代码「看起来能跑」，但只有实际构造边界请求才会暴露问题。
本项目中，路径穿越绕过、全角数字通过校验、中文文件名导致响应中断这三个问题，
都是运行时才暴露的。
